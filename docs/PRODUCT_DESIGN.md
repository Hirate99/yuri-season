# YuriSeason：产品与内容系统设计

## 1. 产品定义

YuriSeason 不是通用动画数据库，也不是自动搬运资讯的聚合站。它是一套围绕“当季值得关注的女性关系动画”建立的可追溯编辑索引：告诉用户本周播什么、作品由谁创作、角色和声优是谁，以及作品公式、创作者、声优和社区最近发生了什么。

站点必须同时做到：

- 用「百合」「关系向」「女性群像」区分内容倾向；证据不足时只标「观察中」。
- 把节目表、百科资料和实时 Feed 连成同一个使用路径。
- 所有动态保留原始来源；AI 只辅助发现、归类、去重和摘要。
- 尊重创作者和社区：不擅自镜像图片或正文，允许来源纠正与创作者退出精选。
- 让 Admin 能在很短时间内完成审核、补关系和发布，而不是维护一堆孤立表格。

## 2. 核心对象

### 2.1 作品与季度

`work` 表示一个可独立追踪的动画条目，例如某一季 TV 动画，而不是整个 IP。续作、剧场版和短篇通过关系连接。

作品保存多语言标题、简介、编辑说明、百合分类、播出状态、制作公司、原作类型、外部条目与视觉主题。`season` 决定当季首页范围，但作品可以跨季度持续播出。

### 2.2 人物、角色与关系

`person` 统一表示作者、监督、脚本、动画师、声优等现实人物。`character` 表示角色。两者都能关联多个作品和多个账号。

- `work_credit`：人物在作品中的 Staff 职务。
- `cast_credit`：声优、角色与作品的三方关系。
- `character_birthday`：月、日、可选年份、时区、来源与验证状态。
- `account`：账号属于作品、人物或组织，并标记平台、句柄、验证状态和采集策略。

人物与角色必须成为一等对象，否则作者贺图、声优动态和角色生日只能退化成无法复用的文本标签。

### 2.3 事件

`event` 是有时间语义的事实，包括：

- 单集播出、首播、配信和延期。
- 角色生日（每年重复）与作品周年。
- 直播、广播、见面会、展览和发售。
- 官方公告中明确给出的未来节点。

事件可以关联作品、人物和角色。首页“今天 / 本周”由事件生成，不从 Feed 文案反推日期。

### 2.4 媒体内容

`media_item` 表示官方视觉图、作者贺图、Staff/Cast 绘图、同人插画、同人视频、Cosplay 等外部作品。

每条必须保存：

- 创作者与原始发布链接。
- 内容类别、发布时间、作品 / 角色关联。
- `presentation_mode`：`link_only`、`platform_embed`、`remote_preview` 或 `mirrored_with_permission`。
- `safety_rating`：`safe`、`suggestive`、`adult`、`unknown`。
- `spoiler_level`：`none`、`mild`、`major`。
- 授权或展示依据；无明确依据时默认 `link_only`。

同人默认不下载、不转存、不绕过防盗链。Admin 可以精选，但公开卡片必须突出作者和原平台，而不是让本站看起来像内容所有者。

### 2.5 来源观察、候选与公开 Feed

采集管线分三层，禁止直接从爬虫写入公开 Feed：

1. `source_observation`：某个来源在某次检查中返回的事实片段、规范化 URL、时间、哈希和有限摘要。
2. `feed_candidate`：去重并完成实体匹配后的待审核候选，包含类别、重要性、置信度、展示建议和风险标记。
3. `feed_item`：审核通过的公开内容，可关联作品、人物、角色、事件与媒体内容。

一条来源观察可以生成多个候选，也可以只更新已有实体。例如官方页面同时公布新角色、声优和首播日期时，资料更新与公开新闻 Feed 分开处理。

## 3. Feed 分类与排序

### 3.1 内容类别

- `schedule`：放送、配信、延期、特别编成。
- `official_news`：PV、KV、制作与活动公告。
- `official_art`：公式贺图、纪念视觉。
- `creator_art`：原作者、Staff 或 Cast 发布的相关创作。
- `birthday`：角色生日与官方 / 社区庆祝内容。
- `cast_post`、`staff_post`：与作品明确相关的重要动态。
- `fanwork`：人工精选同人插画、视频、Cosplay。
- `community_thread`：集中讨论串、字幕与观影信息。
- `editorial`：站点编辑说明或当周观察。

### 3.2 来源身份

每张卡同时显示内容类别和来源身份：`official`、`creator`、`cast`、`community`、`editorial`。来源身份不由 AI 猜测，必须来自已验证账号或人工确认。

### 3.3 排序

默认 Feed 仍按时间倒序，避免不可解释的算法时间线。首页“重要更新”使用确定性得分：

`类别基础分 + 可信来源 + 新鲜度 + 当季相关度 + 人工提升 - 重复 / 风险惩罚`

AI 不能直接修改人工提升，也不能把同人热度当作事实重要性。

## 4. 页面结构

### 4.1 首页

- 顶部是产品导航、当前季度和搜索，不使用营销式巨幅 Slogan。
- “今天 / 本周”节目带同时显示单集播出、生日和直播事件。
- “当季作品”按百合分类、播出日与状态筛选。
- “本季情报流”统一显示公式、作者 / Staff / Cast、生日、同人与社区更新。
- 同人和生日可以单独关闭；成人或未知分级默认不展示。

### 4.2 作品详情

- 作品信息、编辑说明、播出与外部链接。
- Staff、角色 / Cast、已验证账号。
- 作品范围内的日历与 Feed。
- “画廊 / 贺图 / 同人精选”媒体架，始终展示作者与原链接。
- 角色生日列表和未来 30 天提示。
- 贴吧、NGA、百合会、Bangumi 等集中讨论入口与最后活跃时间。
- 数据来源、最后检查时间与纠错入口。

### 4.3 人物与角色

首版可以内嵌在作品详情，数据模型必须支持后续独立页面。

- 人物页：跨作品职务、角色配音、验证账号、作品相关 Feed。
- 角色页：生日、出演作品、声优、相关事件与经过审核的媒体内容。

### 4.4 Admin

- `Inbox`：只收 LLM 无法可靠处理的例外，显示候选摘要、原始链接、来源差异、重复匹配、实体关联和风险提示。
- `Composer`：编辑标题与摘要，附加作品 / 人物 / 角色 / 事件 / 媒体后发布。
- `Works`：作品资料、播出、Staff、Cast 与关系。
- `People & Characters`：账号、生日与来源验证。
- `Media`：展示模式、署名、分级、剧透和授权依据。
- `Sources`：连接器、检查频率、游标、条件请求信息、健康状态与抓取政策。
- `Calendar`：事件编辑与冲突检查。
- `Runs & Audit`：任务结果、失败重试、审核记录与字段变更。

单人维护阶段使用 `ADMIN_TOKEN`；正式公开 Admin 时优先切换 Cloudflare Access，并保留操作审计。

## 5. 采集策略

### 5.1 来源等级

A级（可在 Worker 自动同步）：

- Bangumi 公共 API。
- 公式网站的 RSS、JSON 或稳定 HTML 新闻页。
- YouTube 频道 RSS。
- Bluesky 公共 AppView API、Mastodon 公共 API。

B级（需要凭证或预算）：

- X API。按用量计费，按已验证账号增量读取并设置每日预算；不做全网关键词扫库。
- Cloudflare Browser Run。只对允许域名、必须执行 JavaScript 的页面启用，并设置页数与频率上限。

C级（本地 skill / 人工）：

- Pixiv 与其他无稳定公开接口的同人平台。
- 贴吧、NGA、百合会等社区集中串发现。
- 搜索引擎中的新账号、新贺图与跨平台线索。

### 5.2 Worker Cron

个人站首版采用 `local-first`：Cloudflare 不主动调用模型，本地 Codex 每 6–12 小时或按需运行增量研究，合并成 batch 后写入 Worker。数据库仍保留三档调度能力，方便以后按单个来源逐步启用：

1. 用 D1 租约选择到期来源，限制每轮来源数。
2. 使用 `ETag` / `Last-Modified`、来源游标和稳定条目 ID 增量获取。
3. 规范化并计算条目级内容指纹；唯一约束保证本地 skill 重跑不产生重复候选。首播、最终话与活动窗口使用一次性快速任务，不设置常驻高频轮询。
4. 用确定性规则提取已知结构，再让 Workers AI 进行结构化自动审核。
5. 策略引擎依据 LLM 决定、置信度和硬约束自动发布、暂存或拒绝；只有例外写入 Inbox。
6. 更新来源健康状态和本轮审计。

当来源超过约 50 个、需要大规模 Browser Run 或单轮经常超时后，再把“选源 → 抓取 → 分类 → 入库”升级为 Queue / Workflow。首版不为理论规模支付额外复杂度。

### 5.3 本地 agentic search skill

本地 skill 负责联网搜索与登录态浏览器场景：

1. 从当季作品、核心人物、角色生日和已验证账号生成查询计划。
2. 按公式站 / 原作者 / Staff / Cast / 社区顺序检索。
3. 只提交带可访问原链接、发布时间、来源身份和实体关联的候选。
4. 对同人补充作者、平台、分级、剧透与 `link_only` 展示建议。
5. 通过 Admin ingest API 写入候选，由同一套 LLM 审核策略决定是否自动发布。

## 6. LLM 自动审核

### 6.1 审核输出

每个候选都经过结构化审核，输出固定 JSON：

- `decision`：`publish`、`hold` 或 `reject`。
- `content_class` 与 `source_identity`。
- 匹配到的作品、人物、角色与事件，以及每项置信度。
- `safety_rating`、`spoiler_level` 与建议的 `presentation_mode`。
- 面向公开 Feed 的中文标题和短摘要。
- 决定理由、整体置信度和需要 Admin 注意的风险。

审核记录保存模型、提示版本、输入指纹、输出 JSON、策略结果和发布时间。已自动发布内容可以在 Admin 一键撤回；相同指纹在提示版本不变时不重复消费模型。

### 6.2 自动发布门槛

满足以下条件时允许自动发布：

- 来源账号已由人工或可信官方交叉链接验证。
- 作品 / 人物 / 角色匹配置信度达到策略阈值。
- 原始 URL、发布时间和作者署名完整。
- 媒体内容使用 `link_only` 或经过验证的平台官方嵌入。
- 安全分级不是 `adult` 或 `unknown`，重大剧透默认不进首页。
- 未命中重复、搬运嫌疑、身份冲突、失效链接或提示注入风险。

因此，已验证原作者账号的贺图、已验证角色生日的庆祝内容和标题明确的集中讨论串可以自动上线。新发现同人外链在首阶段始终进入 Inbox，由 Admin 复核原作者、分级与作品关联；低置信或其他风险内容同样进入 Inbox，而不是阻塞整轮任务。

### 6.3 分层审核

- 第一层使用确定性规则处理 URL 规范化、账号验证、时间、重复和硬性政策。
- 第二层使用较小模型完成分类、实体匹配、分级和摘要。
- 只有置信度接近阈值、同人媒体或来源冲突时才使用更强模型复核，控制成本。
- 最终发布由策略引擎执行；来源正文中的任何“指令”都只当作不可信数据，LLM 无权修改账号验证、来源等级或策略阈值。

### 6.4 可以与不可以

可以：

- 对候选做类别建议、实体匹配、去重和短摘要。
- 从官方页面差异中提取日期、Staff / Cast 与链接。
- 标记可能的剧透、成人内容或来源身份冲突，并按置信度自动决定或转入 Inbox。
- 在硬约束通过时自动发布作者贺图、同人外链、生日庆祝与社区串。

不可以：

- 判定账号是否官方并直接写入验证状态。
- 根据人气推断角色关系或百合分类。
- 绕过展示权利、安全分级、剧透和来源身份硬约束。
- 生成不存在的引用、生日或社交账号。

所有 LLM 输出保存模型、提示版本与置信度，方便后续重跑、回滚和审计。

## 7. 视觉语言

- 系统无衬线字体为主，时间与状态使用等宽字体；不使用衬线标题制造“杂志感”。
- 深墨绿色 / 暖灰为底，酸橙作为系统信号色，珊瑚、紫和蓝只作为作品主题。
- 使用清晰网格、细分隔线和紧凑信息密度；减少无意义大圆角、渐变光球和悬浮卡片。
- 未获展示许可的作品使用排版封面，不伪造或抓取视觉图。
- 动效只表达筛选、审核状态与时间线变化，并尊重 `prefers-reduced-motion`。

## 8. 外部能力依据

- Cloudflare Cron Trigger 使用 UTC 并可能重复投递，因此所有写入必须幂等：<https://developers.cloudflare.com/workers/configuration/cron-triggers/>
- Browser Run 可用于受控页面抓取，但应限制允许域名、页数和资源类型：<https://developers.cloudflare.com/browser-run/get-started/>
- Bluesky 作者 Feed 有无需登录的公共端点：<https://docs.bsky.app/docs/api/app-bsky-feed-get-author-feed>
- X API 按读取量计费，应使用精确账号读取、缓存和预算：<https://docs.x.com/x-api/fundamentals/post-cap>
- Bangumi API 与 User-Agent 约定：<https://github.com/bangumi/api>

## 9. 首版验收范围

首版必须完成：

- 当季作品、播出日历、作品详情、Staff / Cast、人物账号。
- 角色与生日事件。
- 统一 Feed 及公式、作者贺图、生日、同人、社区筛选。
- 安全的媒体外链卡片与分级 / 剧透隐藏。
- LLM 自动审核、例外 Inbox、回滚审计、作品资料与来源健康状态。
- Worker Cron 的结构化来源同步和项目内本地 research skill。

首版允许延后：

- 人物 / 角色独立公开页面。
- X API 付费连接器和 Cloudflare Browser Run 自动抓取。
- 多用户 Admin 权限、通知订阅和个性化 Feed。
